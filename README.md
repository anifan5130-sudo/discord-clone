# Voxa — свой голосовой сервер в духе Discord

Голосовые комнаты, демонстрация экрана, камеры и текстовый чат на **вашем собственном сервере**.
Работает в браузере: друзьям достаточно открыть ссылку.

## Возможности

- **Комнаты**: любой участник создаёт свою комнату. Можно задать тему, пароль и лимит участников; создатель может менять настройки и удалять комнату.
- **Качественный звук**: кодек Opus до 192 кбит/с (в Discord без Nitro 64 кбит/с), RED (защита от потерь пакетов), DTX (экономия трафика в тишине).
- **Шумоподавление**: нейросеть RNNoise прямо в браузере убирает клавиатуру, вентиляторы, шум улицы. Плюс порог чувствительности (шумовой гейт), эхоподавление и автоусиление. Все режимы переключаются на лету, без переподключения.
- **Демонстрация экрана**: 720p/1080p/1440p, 30 или 60 FPS (для игр), **со звуком**. Одновременно могут стримить несколько человек.
- **Веб-камера** 360p–1080p.
- **Push-to-talk**: любая клавиша или боковая кнопка мыши, задержка отпускания.
- **Текстовый чат** в каждой комнате: история, ссылки, счётчики непрочитанных.
- Индикация говорящих, громкость каждого участника и каждой трансляции отдельно (ПКМ по участнику), выключение звука (Deafen), выбор микрофона/динамиков, проверка микрофона.
- Горячие клавиши: `Ctrl+Shift+M` — микрофон, `Ctrl+Shift+D` — звук.

## Как устроено

```
Браузер ──HTTPS──► Caddy ──► app (Node.js): сайт, API, чат, комнаты (SQLite)
   │                  └────► LiveKit: сигналинг (/rtc)
   └──── UDP 50000-60000 / TCP 7881 ────► LiveKit (SFU): голос и видео
```

- **LiveKit** — медиасервер (SFU). Каждый отправляет свой поток один раз, сервер раздаёт его остальным. Держит десятки человек в комнате.
- **app** — маленький Node.js-сервер без внешних зависимостей: комнаты, чат, пароли, выдача токенов LiveKit.
- **Caddy** — автоматически получает HTTPS-сертификат (без HTTPS браузеры не дают доступ к микрофону).

## Установка на VPS

Нужно:
- VPS с публичным IP (Ubuntu 22.04/24.04 или Debian 12). Для компании до ~20 человек хватит 2 vCPU / 2 ГБ RAM.
- Домен (или поддомен), A-запись которого указывает на IP сервера. Подойдёт и бесплатный, например от DuckDNS.

```bash
# на сервере
git clone <ваш-репозиторий> voxa   # или загрузите архив и распакуйте
cd voxa
sudo bash install.sh
```

Скрипт спросит домен, название сервера и пароль для входа, сам установит Docker, сгенерирует ключи, откроет порты и запустит всё. В конце покажет **пароль администратора** — введите его при входе вместо пароля сервера, чтобы получить права админа (удаление любых комнат и сообщений).

### Порты

| Порт | Протокол | Зачем |
|---|---|---|
| 80, 443 | TCP | сайт и HTTPS |
| 7881 | TCP | запасной канал для медиа, если UDP закрыт |
| 50000–60000 | UDP | голос и видео |

Если у хостера есть свой файрвол в панели управления — откройте эти порты и там. Порт 7880 наружу открывать **не нужно**.

### Управление

```bash
docker compose logs -f          # логи
docker compose restart          # перезапуск
git pull && docker compose up -d --build   # обновление
```

Данные (комнаты, чат) лежат в папке `data/` — её и стоит бэкапить.

## Настройки (.env)

| Переменная | Описание |
|---|---|
| `DOMAIN` | домен сервера |
| `SERVER_NAME` | название в интерфейсе |
| `SERVER_PASSWORD` | пароль входа (пусто — вход только по нику) |
| `ADMIN_PASSWORD` | пароль администратора |
| `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET` | ключи LiveKit (должны совпадать с `livekit.yaml`) |
| `MAX_ROOMS` | максимум комнат |

После изменения: `docker compose up -d`.

## Трафик сервера

Сервер пересылает каждый поток каждому зрителю, поэтому исходящий трафик ≈ битрейт × число слушателей:

- голос 128 кбит/с, 10 человек → ~1,2 Мбит/с на каждого слушающего, ~12 Мбит/с исходящего;
- стрим 1080p60 (8 Мбит/с) на 10 зрителей → ~80 Мбит/с исходящего.

У большинства VPS канал 100 Мбит/с – 1 Гбит/с, этого хватает с запасом. LiveKit сам снижает качество видео зрителям со слабым интернетом.

## Полезно знать

- **Лучше всего работает в Chrome, Edge, Яндекс Браузере.** В Firefox нейросетевой шумодав может не запуститься — тогда автоматически включается стандартный.
- **Звук демонстрации**: в окне выбора экрана поставьте галочку «Поделиться звуком». На Windows можно передавать звук всей системы, на macOS — только звук вкладки браузера.
- **Push-to-talk** срабатывает, только пока вкладка Voxa в фокусе (ограничение браузеров). Если играете в полноэкранную игру — используйте режим по голосу с порогом чувствительности, RNNoise отлично отсекает клики и клавиатуру.
- Если у кого-то очень строгая корпоративная сеть и не подключается голос — раскомментируйте блок `turn:` в `livekit.yaml`, откройте `3478/udp` и перезапустите.

## Разработка локально

```bash
# 1. LiveKit в dev-режиме (ключи devkey / secret)
docker run --rm -p 7880:7880 -p 7881:7881 -p 7882:7882/udp livekit/livekit-server --dev --bind 0.0.0.0

# 2. Сервер
cd server && npm start           # Node.js 22.13+

# 3. Клиент с горячей перезагрузкой
cd web && npm install && npm run dev   # откройте http://localhost:5173
```

На `localhost` микрофон работает и без HTTPS. Вебхуки в dev-режиме не настроены, поэтому список «кто в комнате» в сайдбаре обновляется раз в минуту — на сервере с `install.sh` всё мгновенно.

## Структура

```
server/index.js        API, чат, комнаты, SSE, вебхуки LiveKit
server/livekit.js      JWT-токены, проверка вебхуков, API LiveKit
web/src/main.js        интерфейс
web/src/voice.js       подключение к LiveKit: голос, экран, камера
web/src/audio/mic.js   цепочка обработки микрофона
web/src/audio/gate-worklet.js   шумовой гейт и push-to-talk (AudioWorklet)
web/src/audio/rnnoise.js        нейросетевое шумоподавление
docker-compose.yml, Caddyfile, livekit.yaml.example, install.sh — деплой
```
